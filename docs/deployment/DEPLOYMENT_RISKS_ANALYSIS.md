**문제:**
- 현재 UtilityToken은 **Upgradeable 패턴이 없음**

- 버그 발견 시 **새 컨트랙트 재배포**만 가능

**영향:**
```solidity
// 현재 구조
contract UtilityToken is ERC20, ERC20Burnable, AccessControl {
    // Upgradeable 없음!
    // Pausable 없음!
}
```

**시나리오:**
1. 배포 후 버그 발견 → ❌ 수정 불가
2. 기능 추가 필요 → ❌ 추가 불가
3. 보안 취약점 발견 → ❌ 패치 불가
4. 유일한 해결책 → 새 토큰 발행 + 마이그레이션

**대응 방안:**
```
단기 (지금):
- 현재 설계 그대로 배포
- 초기 소량으로 테스트 (1,000 DAIM만)
- 1주일 테스트 후 추가 발행

중기 (1개월 후):
- Upgradeable Proxy 패턴 적용한 v2 개발

장기:
- 완전 탈중앙화 거버넌스 도입
```

### 2. **Admin 지갑 권한 집중** 🔐

**문제:**
```
$TOKEN_MAINNET_ADMIN_ROLE 지갑 하나가:
  ├─ DEFAULT_ADMIN_ROLE (모든 권한)
  ├─ MINTER_ROLE (무제한 발행 가능)
  ├─ Deployer (컨트랙트 소유)
  └─ Paymaster 운영
```

**리스크:**
- 이 지갑 해킹 시 → **모든 권한 탈취**
- Private key 유출 시 → **무제한 토큰 발행 가능**
- 단일 실패 지점 (Single Point of Failure)

**시나리오:**
```
해커가 Private Key 탈취 → 
mint(attacker, 1000000000000000) → 
TOKEN 가치 폭락 → 
프로젝트 신뢰도 붕괴
```

**대응 방안:**
```bash
즉시 (배포 후 24시간 내):
1. Gnosis Safe 멀티시그 생성 (3/5 서명)
2. Admin 권한 멀티시그로 이전
3. 원래 지갑은 Minter만 보유

grantRole(DEFAULT_ADMIN_ROLE, GNOSIS_SAFE);
revokeRole(DEFAULT_ADMIN_ROLE, OLD_ADMIN);
```

**권장 구조:**
```
Gnosis Safe (3/5 멀티시그)
  └─ DEFAULT_ADMIN_ROLE

하드웨어 지갑 (Ledger)
  └─ MINTER_ROLE (Paymaster 전용)

Treasury 지갑 (별도 멀티시그)
  └─ 수수료 수령 전용
```

### 3. **무제한 Minting 가능** 💰

**문제:**
```solidity
function mint(address to, uint256 amount) public onlyRole(MINTER_ROLE) {
    _mint(to, amount);
    // 발행 한도 체크 없음!
}
```

**리스크:**
- 실수로 과도한 발행
- 의도하지 않은 인플레이션
- 토큰 가치 희석

**시나리오:**
```
개발자 실수: mint(user, 1000000 * 1e18)
→ 100만 TOKEN 한 번에 발행
→ 의도: 1,000 TOKEN
→ 실수: 1,000,000 TOKEN
→ 취소 불가!
```

**대응 방안:**
```solidity
// 향후 v2에서 추가
uint256 public constant MAX_SUPPLY = 1_000_000_000 * 1e18; // 10억 상한
uint256 public constant MINT_CAP_PER_TX = 10_000 * 1e18; // 거래당 1만

function mint(address to, uint256 amount) public onlyRole(MINTER_ROLE) {
    require(totalSupply() + amount <= MAX_SUPPLY, "Exceeds max supply");
    require(amount <= MINT_CAP_PER_TX, "Exceeds per-tx cap");
    _mint(to, amount);
}
```

**단기 완화책:**
- 매뉴얼 검증: mint 전 다중 확인
- 스크립트에 안전 장치 추가
- 초기 발행량 최소화 (100만 → 10만)
